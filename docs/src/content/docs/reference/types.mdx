Quant features a rich, statically-typed system that provides both safety and flexibility. All variables must have explicit type annotations.

## Primitive Types

### Integer Types

Quant provides flexible integer types with customizable bit sizes and signedness.

#### Basic Integer

```quant
x: int;  // 32-bit signed integer by default
```

#### Custom Bit Size

```quant
small: int<8>;      // 8-bit signed integer
medium: int<16>;    // 16-bit signed integer
large: int<64>;     // 64-bit signed integer
huge: int<128>;     // 128-bit signed integer
```

#### Custom Signedness

```quant
positive: int<32, u>;   // 32-bit unsigned integer
signed: int<32, s>;     // 32-bit signed integer (explicit)
```

**Signedness options:**

- `s` - Signed (can represent negative numbers)
- `u` - Unsigned (only non-negative numbers)

#### Integer Literal Formats

Quant supports multiple number bases:

```quant
decimal: int = 42;        // Decimal (base 10)
hex: int = 0x2A;          // Hexadecimal (base 16)
octal: int = 0o52;        // Octal (base 8)
binary: int = 0b101010;   // Binary (base 2)
```

### Float Types

Floating-point types for decimal numbers.

```quant
f1: float;        // 64-bit float by default
f2: float<32>;    // 32-bit float
f3: float<64>;    // 64-bit float (explicit)
```

**Float literal:**

```quant
pi: float = 3.14159;
e: float<32> = 2.71828;
```

### Boolean Type

Boolean type for true/false values.

```quant
flag: bool = True;
is_valid: bool = False;
```

**Boolean values:**

- `True`
- `False`

### String Type

String type for text data.

```quant
message: str = "Hello, World!";
name: str = "Quant";
```

**String literals** use double quotes (`"`) and support escape sequences:

- `\n` - Newline
- `\t` - Tab
- `\"` - Quote
- `\\` - Backslash

#### String Interpolation

Backtick strings (`` ` `` ... `` ` ``) embed expressions directly inside the string using `{expr}`:

```quant
name: str = "Alice";
age: int = 30;
println(`hello, {name}! you are {age} years old`);
// hello, Alice! you are 30 years old
```

Any expression is valid inside `{...}`:

```quant
a: int = 6;
b: int = 7;
println(`{a} * {b} = {a * b}`);
// 6 * 7 = 42
```

All primitive types are converted to their string representation automatically. Backtick strings desugar to `string.concat` and `string.to_str` calls, so they produce a plain `str` value and can be used anywhere a `str` is expected:

```quant
fn label(key: str, val: int) -> str {
    return `{key}: {val}`;
}
```

### Character Type

Character type for single characters.

```quant
ch: char = 'A';
newline: char = '\n';
```

**Character literals** use single quotes (`'`).

### Void Type

The void type indicates no value.

```quant
fn greet() -> void {
    println("This function returns nothing");
}
```

## Composite Types

### Array Types

Arrays are declared using square brackets around the element type.

#### One-Dimensional Arrays

```quant
numbers: [int];           // Array of integers
values: [float];          // Array of floats
flags: [bool];            // Array of booleans
```

#### Multi-Dimensional Arrays

```quant
matrix: [[int]];          // 2D array (array of arrays)
cube: [[[int]]];          // 3D array
```

#### Arrays with Const Elements

```quant
constants: [const int];           // Array of immutable integers
matrix: [[const int]];            // 2D array of immutable integers
```

See the [Arrays Guide](/guides/arrays/) for more details on array usage.

### Struct Types

Structs define named composite types that group related fields together.

#### Declaration

```quant
struct Point {
    x: int;
    y: int;
}

struct Person {
    name: str;
    age: int;
}
```

#### Instantiation

Create a struct value using the struct name followed by a field initializer block:

```quant
fn main() -> void {
    p: Point = Point { x: 10, y: 20 };
    person: Person = Person { name: "Alice", age: 30 };
}
```

#### Field Access

Use dot notation to read or write fields:

```quant
fn main() -> void {
    p: Point = Point { x: 0, y: 0 };

    // Read
    println(p.x);  // 0

    // Write
    p.x = 5;
    p.y = 15;
    println(`({p.x}, {p.y})`);  // (5, 15)
}
```

#### Structs as Function Parameters

Structs are passed by value like any other type:

```quant
fn distance(p: Point) -> float {
    import math
    xf: float = float(p.x);
    yf: float = float(p.y);
    return math.sqrt(xf * xf + yf * yf);
}

fn main() -> void {
    p: Point = Point { x: 3, y: 4 };
    d: float = distance(p);
    println(d);  // 5.0
}
```

### Function Types

Functions are first-class values in Quant. A function type is written as a parenthesised parameter type list followed by `->` and the return type:

```quant
(int) -> int           // takes one int, returns int
(int, str) -> bool     // takes int and str, returns bool
() -> void             // no parameters, no return value
```

Parameter names are optional in type annotations -`(int) -> int` and `(x: int) -> int` are the same type.

#### Function references

Store a named function in a variable by writing its name without calling it:

```quant
from math import abs

f: (int) -> int = abs;
println(f(-7));    // 7
```

#### Lambda expressions

Use `fn` as an expression to create an anonymous function:

```quant
double: (int) -> int = fn(x: int) -> int { return x * 2; };
println(double(5));    // 10
```

Lambdas use the same `fn(params) -> rettype { body }` syntax as named function declarations, just without a name.

#### Higher-order functions

Pass functions as arguments or accept them as parameters:

```quant
fn apply(f: (int) -> int, x: int) -> int {
    return f(x);
}

fn double(n: int) -> int { return n * 2; }

fn main() -> void {
    result: int = apply(double, 5);                          // named ref: 10
    result2: int = apply(fn(n: int) -> int { return n * 3; }, 5);  // lambda: 15
}
```

#### Arrays of functions

Function values can be stored in arrays like any other value:

```quant
ops: [(int) -> int] = [double, triple];
g: (int) -> int = ops[0];
println(g(4));    // 8
```

**Named function declaration syntax** (top-level or module-level):

```quant
fn name(param1: type1, param2: type2, ...) -> return_type {
    // body
}
```

## Generic Types

Generic functions are parameterized by one or more *type variables* declared in square brackets immediately after the function name. The type checker resolves each type variable to a concrete type at every call site.

### Syntax

```quant
fn name[T](param: T) -> T { ... }
fn name[T, U](a: T, b: U) -> T { ... }
```

Type variables follow the same naming rules as identifiers. By convention single uppercase letters (`T`, `U`, `K`, `V`) are used for unstructured type parameters.

### Type variable scope

Type variables are in scope for the entire function signature and body. They can appear in parameter types, the return type, and local variable declarations:

```quant
fn wrap[T](x: T) -> T {
    copy: T = x;
    return copy;
}
```

### Type inference at call sites

The caller never writes type arguments explicitly. The type checker infers the binding from the concrete argument types:

```quant
fn identity[T](x: T) -> T { return x; }

fn main() -> void {
    n: int   = identity(1);       // T = int
    s: str   = identity("hi");    // T = str
    f: float = identity(3.14);    // T = float
}
```

### Generic function types

A type variable can appear inside a function-type parameter, enabling generic higher-order functions:

```quant
fn map_arr[T, U](arr: [T], f: (T) -> U, n: int) -> [U] {
    result: [U] = [];
    i: int = 0;
    while (i < n) {
        push(result, f(arr[i]));
        i++;
    };
    return result;
}

fn main() -> void {
    nums: [int] = [10, 20, 30];
    doubled: [int] = map_arr(nums, fn(x: int) -> int { return x * 2; }, 3);
    println(doubled[0]);   // 20
}
```

<Aside>
  Quant generics compile to a single set of bytecode instructions per function (type erasure). Runtime values carry no type tags — the type checker guarantees safety statically, with no code duplication or monomorphization overhead.
</Aside>

## Type Qualifiers

### Const Qualifier

The `const` qualifier makes a type immutable after initialization.

```quant
pi: const float = 3.14159;
max_size: const int = 100;

// pi = 3.14;  // Error: cannot modify const variable
```

#### Const in Types

```quant
values: [const int];              // Array of const integers
data: [[const float]];            // 2D array of const floats
```

## Qualified Types

A qualified type combines a base type with optional qualifiers:

```quant
x: int;                   // Plain type
y: const int;             // Qualified with const
z: [const int];           // Array type with const elements
```

## Type Inference

While Quant requires explicit type annotations for variable declarations, it can infer types in certain contexts:

### In Function Calls

```quant
fn calculate() -> int {
    return 42;
}

fn main() -> void {
    x: int = calculate();  // Type of calculate() is known from its signature
}
```

### In Expressions

```quant
fn main() -> void {
    x: int = 10;
    y: int = 20;
    z: int = x + y;  // Type of (x + y) is inferred as int
}
```

## Type Casting

Explicit type conversion uses the target type as a function call:

<Aside type="note">
Quant has no implicit conversions. You must always cast explicitly when mixing `int` and `float`. Forgetting a cast is a compile-time error, not a silent truncation.
</Aside>

```quant
fn main() -> void {
    // Float to int
    x: float = 3.14;
    y: int = int(x);  // y = 3

    // Int to float
    a: int = 42;
    b: float = float(a);  // b = 42.0

    // In expressions
    c: int = int(3.9) + int(2.1);  // c = 5
}
```

## Type Compatibility

### Assignment Compatibility

- Types must match exactly for assignment
- No implicit conversions (must use explicit casting)

```quant
x: int = 42;
y: float = float(x);    // OK: explicit cast
// z: float = x;        // Error: type mismatch
```

### Parameter Compatibility

Function arguments must match parameter types exactly:

```quant
fn add(a: int, b: int) -> int {
    return a + b;
}

fn main() -> void {
    x: int = 10;
    y: int = 20;
    result: int = add(x, y);  // OK: types match

    // z: float = 5.0;
    // add(x, z);  // Error: float doesn't match int parameter
}
```

## Type Sizes and Ranges

### Integer Ranges

Integer value ranges depend on bit size and signedness:

| Type | Bits | Signed Range | Unsigned Range |
|------|------|--------------|----------------|
| `int<8, s>` | 8 | -128 to 127 | N/A |
| `int<8, u>` | 8 | N/A | 0 to 255 |
| `int<16, s>` | 16 | -32,768 to 32,767 | N/A |
| `int<16, u>` | 16 | N/A | 0 to 65,535 |
| `int` (default) | 32 | -2,147,483,648 to 2,147,483,647 | N/A |
| `int<32, u>` | 32 | N/A | 0 to 4,294,967,295 |
| `int<64, s>` | 64 | -(2^63) to (2^63)-1 | N/A |
| `int<64, u>` | 64 | N/A | 0 to (2^64)-1 |

### Float Precision

| Type | Bits | Precision |
|------|------|-----------|
| `float<32>` | 32 | ~7 decimal digits |
| `float` (default) | 64 | ~15 decimal digits |

## Error Types

`orerror(T, E)` is Quant's built-in result type -a value that is either a success of type `T` or a named error `E`. It plays the same role as `Result<T, E>` in Rust or `Either` in Haskell.

### Declaring Error Types

```quant
error DivisionError;
error ParseError;
error OutOfBounds;
```

Error types with payload fields are also supported:

```quant
error NetworkError { code: int }
error ValidationError { field: str }
```

### Returning orerror Values

A function declares it can fail by using `orerror` as its return type:

```quant
fn safe_div(a: int, b: int) -> orerror(int, DivisionError) {
  if (b == 0) {
    return error DivisionError;
  };
  return a / b;
}
```

Returning a plain value (`return a / b`) is the success path. Returning `error Name` is the error path.

### Handling orerror Values

<Tabs>
  <TabItem label="match (branch on outcome)">
    Use `match` to handle both the success and error cases explicitly. The `ok(v)` arm binds the success value; `err(E v)` binds the error value (including its fields):

    ```quant
    error DivisionError { msg: str };

    fn safe_div(a: int, b: int) -> orerror(int, DivisionError) {
      if (b == 0) {
        return error DivisionError { msg: "division by zero" };
      };
      return a / b;
    }

    fn main() -> void {
      result: orerror(int, DivisionError) = safe_div(10, 0);

      match result {
        ok(n)              => println(`quotient: {n}`);
        err(DivisionError e) => println(`failed: {e.msg}`);
      };
      // Output: failed: division by zero
    }
    ```
  </TabItem>
  <TabItem label="must (unwrap or panic)">
    Use `must` to unwrap the success value, panicking at runtime if it is an error:

    ```quant
    x: int = must safe_div(10, 2);   // x = 5
    y: int = must safe_div(10, 0);   // runtime panic: unwrapped error DivisionError
    ```

    Use `must` when you are certain the call will succeed, or intentionally want a hard crash on failure.
  </TabItem>
  <TabItem label="try (propagate)">
    Use `try` to unwrap the success value and **propagate** the error upward if the call fails. The surrounding function must also return an `orerror` with a compatible error type:

    ```quant
    fn double_div(a: int, b: int, c: int) -> orerror(int, DivisionError) {
      x: int = try safe_div(a, b);     // propagates if b == 0
      return try safe_div(x, c);       // propagates if c == 0
    }
    ```

    If `safe_div` returns an error, `try` immediately returns that error from `double_div` -no further statements execute.
  </TabItem>
</Tabs>

<Aside type="caution">
  `try` can only be used inside a function whose return type is `orerror(_, E)` where `E` matches the propagated error type.
</Aside>

### Accessing error payload fields

When you bind the error with `err(E v)` in a `match`, the variable `v` holds the full error value and you can read its fields with dot notation:

```quant
error HttpError { code: int, body: str };

fn fetch() -> orerror(str, HttpError) {
    return error HttpError { code: 404, body: "Not Found" };
}

fn main() -> void {
    match fetch() {
        ok(data)        => println(data);
        err(HttpError e) => println(`HTTP {e.code}: {e.body}`);
    };
    // Output: HTTP 404: Not Found
}
```

### Full Example

```quant
error DivisionError;

fn safe_div(a: int, b: int) -> orerror(int, DivisionError) {
  if (b == 0) {
    return error DivisionError;
  };
  return a / b;
}

fn main() -> void {
  ok: int = must safe_div(100, 4);
  println(`result: {ok}`);
}
```

```text
result: 25
```
