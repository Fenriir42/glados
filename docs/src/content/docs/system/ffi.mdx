Quant's `extern` block lets you call functions from any C shared library (`.so` / `.dylib`) without writing any Haskell glue code. Under the hood the VM uses `dlopen`/`dlsym` and [libffi](https://sourceware.org/libffi/) to dispatch the call at runtime.

---

## Syntax

```quant
extern "libname.so.N" {
    fn symbol_name(param: type, ...) -> return_type
}
```

- The string is a library path or bare SONAME (`libm.so.6`, `/usr/lib/libpng.so`).
- Each `fn` line declares one C symbol. No body is written, the VM resolves it at runtime.
- Multiple functions from the same library go in one block.

---

## Supported types

| Quant type | C type |
|---|---|
| `int` | `int64_t` |
| `float` | `double` |
| `bool` | `uint32_t` (0 / 1) |
| `str` | `const char*` |
| `void` | `void` |

<Aside type="caution">
Pointer types beyond `str`, raw C structs, and variadic functions are not yet supported. For those, write a thin C wrapper and bind to it.
</Aside>

---

## Example: libm

```quant
extern "libm.so.6" {
    fn sqrt(x: float) -> float
    fn fabs(x: float) -> float
    fn pow(base: float, exp: float) -> float
}

fn main() -> void {
    println(sqrt(2.0));     // 1.4142135623730951
    println(fabs(-3.14));   // 3.14
    println(pow(2.0, 10.0)); // 1024.0
}
```

---

## Example: libc string utilities

```quant
extern "libc.so.6" {
    fn strlen(s: str) -> int
    fn atoi(s: str) -> int
}

fn main() -> void {
    n: int = strlen("hello");
    println(n);           // 5

    x: int = atoi("42");
    println(x);           // 42
}
```

---

## Example: multiple libraries

```quant
extern "libm.so.6" {
    fn sin(x: float) -> float
    fn cos(x: float) -> float
}

extern "libc.so.6" {
    fn rand() -> int
    fn srand(seed: int) -> void
}

fn main() -> void {
    srand(42);
    println(rand());
    println(sin(1.5708)); // ~1.0
}
```

## Callbacks: passing Quant functions to C

An `extern` function may declare a parameter with a function type. Passing a Quant function there hands C a real function pointer; when C calls it, execution re-enters the Quant VM:

```quant
extern "libc.so.6" {
    fn malloc(size: int) -> ptr
    fn free(p: ptr) -> void
    fn qsort(base: ptr, nmemb: int, size: int, compar: (ptr, ptr) -> int) -> void
}

fn compare_asc(a: ptr, b: ptr) -> int {
    x: int = ptr.read_int32(a);
    y: int = ptr.read_int32(b);
    return x - y;
}

fn main() -> void {
    n: int = 4;
    buf: ptr = malloc(n * 4);
    vals: [int] = [42, 7, 19, 3];
    for (i: int = 0; i < n; i++) {
        ptr.write_int32(ptr.add(buf, i * 4), vals[i]);
    };
    qsort(buf, n, 4, compare_asc);
    free(buf);
}
```

The callback may read and write the VM's heaps (arrays, dicts, structs); mutations persist across invocations and after the C call returns. A runtime error raised inside a callback is re-thrown once the C function returns.

Callbacks may take any number of arguments from zero up to four -- for
example `qsort`'s 2-argument comparator or `qsort_r`'s 3-argument
`(a, b, arg) -> int`. Each C argument is delivered to the Quant function as a
`ptr`, and the function returns an `int` (a `bool` is converted to 0/1); a C
callback declared to return `void` simply ignores the returned value. All
callback arguments are passed as pointer-sized values, so callbacks whose C
signature takes floating-point or narrower-than-pointer integer arguments are
not yet supported.

### Raw memory access

The `ptr` module provides byte-level access to C memory for use inside callbacks and around `malloc`-style APIs:

| Function | Signature | Description |
|----------|-----------|-------------|
| `ptr.add` | `(p: ptr, off: int) -> ptr` | Pointer plus byte offset |
| `ptr.read_int32` | `(p: ptr) -> int` | Read a 32-bit signed int |
| `ptr.write_int32` | `(p: ptr, v: int) -> void` | Write a 32-bit signed int |
| `ptr.read_int64` | `(p: ptr) -> int` | Read a 64-bit signed int |
| `ptr.write_int64` | `(p: ptr, v: int) -> void` | Write a 64-bit signed int |
| `ptr.read_float64` | `(p: ptr) -> float` | Read a C double |
| `ptr.write_float64` | `(p: ptr, v: float) -> void` | Write a C double |

These operate on raw addresses with no bounds checking -- reading or writing through an invalid pointer crashes the process, exactly like C.

## Runtime behaviour

- Libraries are opened with `RTLD_LAZY` on the first call and cached for the lifetime of the program, `dlopen` is not called again on subsequent calls.
- A missing symbol or library causes a runtime error with the library path and symbol name.
- `str` arguments are converted to a temporary `CString` for the duration of the call and freed immediately after. Passing a `str` to a function that stores the pointer beyond the call is unsafe.
- Functions returning `str` call `peekCString` on the returned pointer immediately. The pointer must remain valid for that instant (e.g. static strings, `strerror`). Use caution with functions that return `malloc`-ed strings, there is currently no way to call `free` on them from Quant.

---

## Finding the right SONAME

On Linux, use `ldconfig` or `ldd` to find the versioned name:

```bash
ldconfig -p | grep libm
#   libm.so.6 => /lib/x86_64-linux-gnu/libm.so.6

ldconfig -p | grep libpng
#   libpng16.so.16 => /lib/x86_64-linux-gnu/libpng16.so.16
```

Use the versioned name (e.g. `libpng16.so.16`) in the `extern` string for portability.
